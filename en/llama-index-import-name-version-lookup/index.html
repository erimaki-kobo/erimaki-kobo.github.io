ImportError: cannot import name 'VectorStoreIndex' (or ServiceContext, OpenAI, any name) from 'llama_index...': which LlamaIndex releases have it

LlamaIndex 0.10.0 (2024-02-10) moved the whole old top level into llama_index.core and split every integration into its own package; 0.9.48 is the last release with the old layout. from llama_index import VectorStoreIndex becomes from llama_index.core import VectorStoreIndex. from llama_index.llms import OpenAI becomes pip install llama-index-llms-openai and from llama_index.llms.openai import OpenAI; embeddings, vector stores and readers work the same way. ServiceContext still imports but fails from 0.11.0: use Settings. llama-index-core 0.13.0 removed the old agents (AgentRunner) and QueryPipeline, and 0.14.21 removed download_loader. For any other name, paste the error below; the lookup gives the new import and the package for 580 old names.

What changed after 0.10?

  • 0.11.0 (2024-08-22): ServiceContext raises on use; Settings (from 0.10.1) replaces it. llama_index.core.workflow arrives.
  • 0.13.0 (2025-07-30): llama_index.core.query_pipeline and the old agent classes (AgentRunner, ReActAgentWorker, FunctionCallingAgentWorker, StructuredPlannerAgent and more) are gone; use llama_index.core.agent.workflow (FunctionAgent and AgentWorkflow from 0.12.12).
  • 0.14.21 (2026-04-21): download_loader, llama_index.core.download, llama_dataset and llama_pack are gone; install the reader or pack package directly.

How do I read the error?

  • Check both packages: pip show llama-index llama-index-core. From 0.10 the code is in llama-index-core; the llama-index package only pulls it in with a few integrations.
  • A mixed install (an old llama-index 0.9 next to llama-index-core) makes imports fail in surprising ways. Uninstall both and install one side.
  • An integration name (llama_index.llms.openai, llama_index.vector_stores.chroma) that fails with "No module named" means its package is not installed; the lookup names the package.

How was this read, and how was it checked?

From the Python files of every release's wheel on PyPI (llama-index 0.7.0 to 0.9.48, llama-index-core 0.10.0 to 0.14.26), read by HTTP range requests and parsed with Python's ast module. The git tags were not used for the data: the v0.10.0 tag exports Settings, the published 0.10.0 wheel does not. A module's names are everything it binds at module level and what from .x import * brings in; names that appear only in __all__ without a binding (0.9.0 lists BeautifulSoupWebReader) are not importable and are not counted. Integration packages are not read; their imports come from the upgrade map.

Checks: (1) the top-level names of each part are found as plain text in its __init__.py in every release of their range (37,235 name-and-release pairs) and are not bound on either side (64 edges). (2) A regular expression finds 31,574 definitions in 7,397 file versions; all are among the names read. (3) 14 release checks against the wheels by plain-text search agree:

Limits

  • Nothing was installed or run. "Has it" means the import statement resolves in the Python files of the wheel.
  • llama-index before 0.7.0 is not covered (0.6 and older had no pure-Python wheel of this layout).
  • Integration packages (llama-index-llms-*, -embeddings-*, -vector-stores-*, -readers-*) have their own versions and are not read; for them the page gives the import and the package from the upgrade map.

Questions

How do I fix "cannot import name 'VectorStoreIndex' from 'llama_index'"?

LlamaIndex 0.10.0 (2024-02-10) moved it: from llama_index.core import VectorStoreIndex. The same holds for SimpleDirectoryReader, StorageContext, Document, load_index_from_storage and the rest of the old top level; 0.9.48 is the last release with the old layout. To keep old code unchanged, pin pip install "llama-index<0.10.0".

How do I fix "cannot import name 'OpenAI' from 'llama_index.llms'"?

From 0.10.0 each integration is its own package: pip install llama-index-llms-openai, then from llama_index.llms.openai import OpenAI. Embeddings and vector stores work the same way, for example llama-index-embeddings-openai and llama-index-vector-stores-chroma. The table on this page and the lookup give the package for 708 names.

ServiceContext imports but fails. What replaces it?

From 0.11.0 (2024-08-22) creating a ServiceContext raises "ServiceContext is deprecated. Use llama_index.settings.Settings instead". Set Settings.llm, Settings.embed_model, Settings.chunk_size and so on, or pass the objects to the functions that use them. Settings is in llama_index.core from 0.10.1.

Where did AgentRunner, FunctionCallingAgentWorker and QueryPipeline go?

llama-index-core 0.13.0 (2025-07-30) removed the old agent classes and query pipelines. Agents are workflow-based: llama_index.core.agent.workflow has FunctionAgent, ReActAgent and AgentWorkflow; pipelines are written as workflows (llama_index.core.workflow, from 0.11.0).

Why does "from llama_index.core import download_loader" fail now?

llama-index-core 0.14.21 (2026-04-21) removed download_loader together with llama_index.core.download, llama_dataset and llama_pack. Install the reader package instead, for example pip install llama-index-readers-file.
