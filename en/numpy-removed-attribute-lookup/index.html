AttributeError: module 'numpy' has no attribute 'float_' (or 'float', 'NaN', 'product', any name): which NumPy removed it and what to use

NumPy 1.24.0 (2022-12-18) removed np.float, np.int, np.bool, np.object, np.str, np.complex, np.long and np.unicode: use the Python builtins (float, int) or NumPy types (np.float64). NumPy 2.0.0 (2024-06-16) removed 77 more, among them np.float_ (use np.float64), np.NaN (np.nan), np.Inf (np.inf), np.complex_ (np.complex128) and np.product (np.prod). 2.4 removed np.trapz and np.in1d, 2.5 np.row_stack. If the error comes from a library you did not write, upgrade the library or pin NumPy below the release that removed the name. Paste the error below for the release-by-release answer.

How was this measured?

Each of 15 NumPy releases was installed from PyPI in its own environment and getattr(numpy, name) was run for every name, recording whether it worked, which warning it gave, and the exact AttributeError text. Releases: 1.19.5 (Python 3.9), 1.20.0 (Python 3.9), 1.21.0 (Python 3.9), 1.22.0 (Python 3.10), 1.23.0 (Python 3.10), 1.24.0 (Python 3.11), 1.25.0 (Python 3.11), 1.26.0 (Python 3.11), 2.0.0 (Python 3.12), 2.1.0 (Python 3.12), 2.2.0 (Python 3.12), 2.3.0 (Python 3.12), 2.4.1 (Python 3.12), 2.5.0 (Python 3.12), 2.5.5 (Python 3.12). The names are those in the tables NumPy's module __getattr__ answers from (__deprecated_attrs__, __expired_functions__, __former_attrs__, __future_scalars__, numpy/_expired_attrs_2_0.py) in the first release of every minor from 1.16, plus a few removed without an entry. Those tables were also read from the source at the release tags: all 609 entries predict what the installed release did, with no mismatch.

The table covers access to the attribute. Some names (np.product in 1.25 and 1.26) warn only when called, so they show here as "works".

Questions

How do I fix "module 'numpy' has no attribute 'float'" (or 'int', 'bool', 'object')?

NumPy 1.24.0 (2022-12-18) removed these aliases of the Python builtins; 1.20 to 1.23 warned. Use float, int, bool, object (the builtins) or the NumPy types np.float64, np.int64, np.bool_. From 1.25 the error explains this. np.bool and np.long exist again from 2.0, now as NumPy types (np.bool is np.bool_). If the error comes from a library, upgrade it, or pin numpy<1.24.

How do I fix "`np.float_` was removed in the NumPy 2.0 release"?

Use np.float64. NumPy 2.0.0 (2024-06-16) removed 77 names; 54 of them answer with a message naming the replacement (np.NaN to np.nan, np.Inf to np.inf, np.complex_ to np.complex128, np.string_ to np.bytes_, np.unicode_ to np.str_). The others fail with the plain AttributeError; the table on this page gives their replacement from the deprecation warning they showed before.

Why does "No module named 'numpy._core'" appear?

numpy._core exists from NumPy 2.0 (numpy.core before). A pickle, joblib or model file written with NumPy 2 refers to numpy._core, so loading it under NumPy 1.x fails. Load it with NumPy 2, or write it again under the NumPy you load it with.

What does "A module that was compiled using NumPy 1.x cannot be run in NumPy 2.0.0" mean?

An installed package has a C extension built against NumPy 1.x. NumPy 2 prints this from numpy/core/_multiarray_umath.py and suggests the two fixes: upgrade that package to a release built for NumPy 2, or pin numpy<2.

np.trapz and np.in1d stopped working. What changed?

NumPy 2.4 removed them (2.4.0 was yanked from PyPI; 2.4.1 is the first 2.4 release). Use np.trapezoid and np.isin. NumPy 2.5 removed np.row_stack (use np.vstack) and np.chararray from the main namespace.
