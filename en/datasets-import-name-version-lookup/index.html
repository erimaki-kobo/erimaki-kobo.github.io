ImportError: cannot import name 'X' from 'datasets' (load_metric, list_datasets, ...): which releases have it

Most of these errors come from datasets 3.0.0 (2024-09-11), which removed 30 top-level names; 2.21.0 is the last release that has them. load_metric, list_metrics and Metric moved to the Evaluate library (evaluate.load). list_datasets is now huggingface_hub.list_datasets. set_caching_enabled is now enable_caching or disable_caching. The task templates, such as TextClassification, were dropped with no replacement in datasets. To run old code unchanged, pin pip install "datasets<3.0.0". For any other name, in any module of datasets, paste the error below.

How do I read the error?

  • The path in parentheses is the copy of datasets that was imported. If it points into your project (a folder or a file named datasets), that shadows the library: rename yours. (unknown location) means a datasets folder without __init__.py was found first.
  • The module after "from" decides which table applies: from 'datasets' is the top level, from 'datasets.arrow_writer' is that module. When another library raises it (trl, for example, imports SchemaInferenceError from datasets.arrow_writer, which exists from 2.7.0), upgrade datasets, not that library.
  • In a notebook, restart the kernel after pip install -U datasets; the old copy stays loaded until then.

How was this read, and how was it checked?

From the source of each release tag, with Python's ast module; no release was installed or imported. datasets imports eagerly, so a module's names are everything it binds at module level: classes, functions, assignments, imports, and what from .x import * brings in. Code under if TYPE_CHECKING: is skipped. Dates come from PyPI.

Checks, by a second reading: (1) each of the 237 top-level names is found as plain text in __init__.py (or in the modules it star-imports) in every release of its range (7,032 name-and-release pairs), and is not imported there in the release on either side (178 edges). (2) A regular expression finds 23,287 definitions in 1,826 file versions; all are among the names read. (3) 8 known facts hold, among them the release named in the public reports under Sources.

Limits

  • Nothing was installed or run. "Has it" means the import statement resolves in the source.
  • Only the first release of each minor version was read (and the newest). A change in a patch release is attributed to the next minor.
  • A star import of a package carries along the submodules that package has loaded; the lookup counts all of its submodules, so for a few old releases it may list a submodule name at the top level that was not loaded yet.
  • Errors that are not about import names, such as dataset loading scripts no longer being run, are not covered.

Questions

How do I fix "cannot import name 'load_metric' from 'datasets'"?

datasets 3.0.0 (2024-09-11) removed load_metric; 2.21.0 is the last release with it. Install the Evaluate library and use evaluate.load: pip install evaluate, then import evaluate; metric = evaluate.load("accuracy"). To keep old code unchanged, pin pip install "datasets<3.0.0".

What else did datasets 3.0.0 remove?

30 top-level names: load_metric, list_metrics, inspect_metric, Metric and MetricInfo (moved to Evaluate), list_datasets (use huggingface_hub.list_datasets), set_caching_enabled (use enable_caching or disable_caching), inspect_dataset, the task templates such as TextClassification, and a few modules. The full list is on this page.

How do I fix "cannot import name 'list_datasets' from 'datasets'"?

Use huggingface_hub.list_datasets, which datasets 2.21.0 already pointed to. datasets 3.0.0 removed its own list_datasets.

The error says "cannot import name ... from 'datasets'" and the path ends in a folder of my project. What is wrong?

A file or folder named datasets in your project (or an old datasets.py) is imported instead of the library. The path in parentheses shows which one; rename yours. The same holds for "unknown location", which means a datasets folder without __init__.py.

Does this page cover names below the top level, like datasets.utils or datasets.arrow_writer?

Yes: every module of datasets from 1.0.0 to 5.2.0, 4,933 module-and-name pairs in 189 modules.
