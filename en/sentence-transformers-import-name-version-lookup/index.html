ImportError: cannot import name 'X' from 'sentence_transformers' (or .models, .util, .losses, ...): which versions have it

Old import paths still work: sentence-transformers 5.4.0 (2026-04-09) moved its modules but serves 133 old paths through an import hook, with a DeprecationWarning. So an import that fails is usually one of these. models.BERT, models.RoBERTa and the other per-architecture modules left in 2.0.0 (2021-06-24); use models.Transformer. util.snapshot_download left in 5.1.0 (2025-08-06); import it from huggingface_hub. cannot import name 'cached_download' from 'huggingface_hub' while importing sentence_transformers means your sentence-transformers is older than 2.3.0 (2024-01-29): upgrade it. How was this read, and how was it checked?

From the source of each release tag, with Python's ast module; no release was installed or imported. A module's names are everything it binds at module level. The old paths come from the aliases each release installs: the DEPRECATED_MODULE_PATHS table and its import hook (5.4.0 on), and direct sys.modules[...] assignments (4.0.0 on); an old path gets the names of the module it points to. Dates come from PyPI.

Checks, by a second reading: (1) each of the 79 top-level names is found as plain text in __init__.py, or is a module, in every release of its range (1,149 name-and-release pairs). (2) A regular expression finds 4,645 definitions in 1,700 file versions; all are among the names read. (3) A regular expression finds the same 1,100 aliases (summed over releases) as the reading. (4) 8 known facts hold.

Limits

  • Nothing was installed or run. "Has it" means the import statement resolves in the source.
  • Only the first release of each minor version was read (and the newest). A change in a patch release is attributed to the next minor.
  • The deprecated paths may be removed in a future release; the hook's message says so. The lookup follows the release you give.

Questions

Does "from sentence_transformers.models import Transformer" still work after 5.4.0?

Yes. sentence-transformers 5.4.0 (2026-04-09) moved its modules, for example sentence_transformers.models to sentence_transformers.sentence_transformer.modules, and installs an import hook that serves 133 old paths from their new places, with a DeprecationWarning. An old path that fails on 5.4.0 or later fails for another reason: the name was removed, or it was never in that module.

How do I fix "cannot import name 'BERT' from 'sentence_transformers.models'"?

sentence-transformers 2.0.0 (2021-06-24) removed the per-architecture modules (BERT, RoBERTa, DistilBERT, XLNet and others). Use models.Transformer("bert-base-uncased"), which loads any Hugging Face model, or pin pip install "sentence-transformers<2.0.0".

Importing sentence_transformers fails with "cannot import name 'cached_download' from 'huggingface_hub'". What do I upgrade?

sentence-transformers. Releases before 2.3.0 (2024-01-29) import cached_download, which huggingface_hub removed in 0.26.0. pip install -U "sentence-transformers>=2.3.0" fixes it; the huggingface_hub page linked below has the details.

Where did sentence_transformers.util.snapshot_download go?

sentence-transformers 5.1.0 (2025-08-06) turned util into a package and stopped passing snapshot_download along. Import it from huggingface_hub, where it always came from.
