AttributeError: module 'matplotlib.cm' has no attribute 'get_cmap' (or 'FigureCanvasAgg' object has no attribute 'tostring_rgb', 'seaborn' is not a valid package style, any name): which matplotlib removed it and what to use

matplotlib 3.11.0 (2026-06-12) removed matplotlib.cm.get_cmap: use matplotlib.colormaps[name] or plt.get_cmap(name) (3.9.0 had removed it too; 3.9.2 put it back). 3.10.0 removed FigureCanvasAgg.tostring_rgb: use np.asarray(fig.canvas.buffer_rgba()). 3.8.0 dropped the 'seaborn-*' style names: use 'seaborn-v0_8-*'. 3.9.0 removed cm.register_cmap and Legend.legendHandles (legend_handles). How was this measured?

Each of 48 matplotlib releases (every release with a Linux x86-64 wheel from 3.1.2 to 3.11.2, patch releases included) was installed from PyPI in its own environment, the public names of 31 matplotlib modules and of 10 classes were listed with dir(), and getattr was run for the union of all names in every release. A class member that is not on the class (set in __init__, as Legend.legendHandles was before 3.7) was checked with hasattr on a real object of that class, built on the Agg canvas. Every style name was tried with plt.style.context(name). Releases: 3.1.2, 3.1.3 (Python 3.8); 3.2.0, 3.2.1, 3.2.2 (Python 3.8); 3.3.0, 3.3.1, 3.3.2, 3.3.3, 3.3.4 (Python 3.8); 3.4.0, 3.4.1, 3.4.2, 3.4.3 (Python 3.9); 3.5.0, 3.5.1, 3.5.2, 3.5.3 (Python 3.9); 3.6.0, 3.6.1, 3.6.2, 3.6.3 (Python 3.10); 3.7.0, 3.7.1, 3.7.2, 3.7.3, 3.7.4, 3.7.5 (Python 3.11); 3.8.0, 3.8.1, 3.8.2, 3.8.3, 3.8.4 (Python 3.12); 3.9.0, 3.9.2, 3.9.3, 3.9.4 (Python 3.12); 3.10.0, 3.10.1, 3.10.3, 3.10.5, 3.10.6, 3.10.7, 3.10.8, 3.10.9 (Python 3.12); 3.11.0, 3.11.1, 3.11.2 (Python 3.12). 3.9.1 is yanked on PyPI and is not in the table; 3.1.0 and 3.1.1 have no wheel for the Pythons used here.

Most matplotlib modules have no __all__, so the table keeps class members, __all__ names and the names matplotlib itself deprecated (a warning on access, or an _api.deprecated decorator or warning in the definition); helpers a module merely imported are left out, but the lookup still answers for them. The text is read from the installed source of the last release that had the name; @_api.deprecated("3.8", alternative="buffer_rgba") is turned into a sentence of the same content.

Questions

How do I fix "module 'matplotlib.cm' has no attribute 'get_cmap'"?

matplotlib 3.11.0 (2026-06-12) removed matplotlib.cm.get_cmap; it was deprecated in 3.7. 3.9.0 had removed it too; 3.9.1 (yanked on PyPI) and 3.9.2 put it back. Use matplotlib.colormaps[name] (from 3.5.0) or matplotlib.colormaps.get_cmap(name), or plt.get_cmap(name), which is still in 3.11.2. cm.register_cmap went in 3.9.0: use matplotlib.colormaps.register(cmap, name=...).

How do I fix "'FigureCanvasAgg' object has no attribute 'tostring_rgb'"?

matplotlib 3.10.0 (2024-12-14) removed tostring_rgb; it was deprecated in 3.8. Use fig.canvas.draw() and then np.asarray(fig.canvas.buffer_rgba()), an (height, width, 4) RGBA array; take [..., :3] for RGB. tostring_argb is still there in 3.11.2.

How do I fix "'seaborn' is not a valid package style"?

matplotlib 3.6.0 renamed its seaborn styles to seaborn-v0_8-<name> and warned on the old names; 3.8.0 (2023-09-15) dropped the old names. Use plt.style.use('seaborn-v0_8-whitegrid') (or the matching name), or seaborn's own seaborn.set_theme().

How do I fix "'Legend' object has no attribute 'legendHandles'"?

matplotlib 3.9.0 removed legendHandles; it was deprecated in 3.7. Use legend.legend_handles (a list, same content).

How do I fix "'Axes' object has no attribute 'plot_date'"?

matplotlib 3.11.0 removed Axes.plot_date and pyplot.plot_date; they were deprecated in 3.9. Pass the dates to ax.plot directly (datetime or numpy datetime64 values are converted for you), with linestyle and marker as you want.
