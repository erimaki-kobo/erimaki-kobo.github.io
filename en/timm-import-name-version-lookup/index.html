ImportError: cannot import name 'X' from 'timm.models.layers', No module named 'timm.layers' or 'timm.models.layers.norm': which timm versions have it

Almost all of these come from timm 0.9.0 (2023-05-12), which moved timm.models.layers to timm.layers and removed 65 modules. No module named 'timm.layers' means your timm is older than 0.9.0: upgrade. No module named 'timm.models.layers.norm' (or .helpers, .drop, ...) means code or a pickled model from timm 0.6.13 or older: the file is now timm.layers.norm, or pin pip install "timm<0.9.0". from timm.models.layers import X still works for the names that existed in 0.9.0, with a FutureWarning, but not for the 127 names added to timm.layers since. For any other module or name, paste the error below.

Which modules did timm 0.9.0 remove, and where are they now?

65 modules left in 0.9.0; for 61 of them a module with the same file exists in 1.0.31, under timm.layers for the old layer files and with a leading underscore for the builders and helpers under timm.models. An import that names one of these modules fails on 0.9.0 and later, and so does loading a model pickled with timm 0.6.13 or older that used them.

79 of the 382 modules that have existed are gone from 1.0.31. Old paths such as timm.models.helpers and timm.models.registry still exist as mapping files that re-export the underscored modules.

The error appears when I load a saved model. What then?

A model saved whole with torch.save(model, path) stores the module path of every class, and loading it imports those paths. A model saved under timm 0.6.13 or older names modules such as timm.models.layers.norm, so loading it with timm 0.9.0 or later raises ModuleNotFoundError from inside pickle (the traceback shows find_class). Load it once with pip install "timm<0.9.0", save model.state_dict(), and from then on build the model with timm.create_model and load the state dict.

How was this read, and how was it checked?

From the source of each release tag, with Python's ast module; no release was installed or imported. timm imports eagerly, so a module's names are everything it binds at module level, including what from timm.layers.x import * brings in. Dates come from PyPI.

Checks, by a second reading: (1) each of the 28 top-level names is found as plain text in __init__.py (or the modules it star-imports) in every release of its range (1,090 name-and-release pairs). (2) A regular expression finds 43,256 definitions in 2,351 file versions; all are among the names read. (3) timm.models.layers was read a second time with regular expressions in all 38 releases where it is a mapping; the names match, apart from torch, nn and F, which a star import without __all__ also passes along. (4) 8 known facts hold, among them the reports under Sources.

Limits

  • Nothing was installed or run. "Has it" means the import statement resolves in the source.
  • Releases on PyPI without a git tag are not read: the early 0.1.x releases with even numbers and 0.3.0 to 0.3.2.
  • A name that works through the 0.9 mapping also prints a FutureWarning; the lookup does not mark that.

Questions

How do I fix "No module named 'timm.models.layers.norm'"?

timm 0.9.0 (2023-05-12) removed the submodules of timm.models.layers; the files moved to timm.layers (timm.layers.norm). The error usually comes from loading a model that was saved whole with torch.save(model) under timm 0.6.13 or older: pickle stores the old module path. Either install pip install "timm<0.9.0" to load it, or load it once there and save model.state_dict() instead, which does not depend on module paths.

How do I fix "No module named 'timm.layers'"?

Your timm is older than 0.9.0. Upgrade with pip install -U "timm>=0.9.0", or, if you must stay on 0.6, import the same names from timm.models.layers.

Does "from timm.models.layers import X" still work?

For the names that existed when timm.models.layers was moved, yes: timm keeps it as a mapping that warns "Importing from timm.models.layers is deprecated, please import via timm.layers". 127 public names added to timm.layers since then are not in the mapping, so for those the old path fails; import them from timm.layers.

Why does this page read every timm release and not one per minor version?

timm has stayed at 1.0 since 2024 and ships its changes in patch releases (1.0.3 to 1.0.31), so a module or name can appear or go in any of them.
