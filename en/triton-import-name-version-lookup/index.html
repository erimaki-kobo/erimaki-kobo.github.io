No module named 'triton.ops', cannot import name 'libdevice' or 'triton_key' from 'triton...': which Triton releases have it

Triton 3.2.0 (2025-01-22) removed triton.ops (matmul, flash_attention, blocksparse, matmul_perf_model); 3.1.0 is the last release with it. Most "No module named 'triton.ops'" errors come from bitsandbytes 0.45.0 and older, which import it as soon as Triton is installed; PyTorch 2.6.0 and later install Triton 3.2 or newer. Upgrade bitsandbytes to 0.45.1 or later. The other common ones: from triton.language.extra.cuda import libdevice needs Triton 3.0.0 or newer (PyTorch 2.4.0 or newer), and PyTorch 2.6 to 2.8 report "Cannot find a working triton installation" with Triton 3.5.0 or newer, because they look for triton_key, which 3.5.0 removed. Install the Triton your PyTorch pins (table below). For any other name, in any module of Triton, paste the error below.

How do I read the error?

  • The file in the traceback tells you whose import it is. bitsandbytes/triton/... means bitsandbytes (upgrade it); torch/utils/_triton.py or torch/_inductor/... means a PyTorch and Triton pair that do not match.
  • Windows: the triton package on PyPI has Linux wheels only. Community builds such as triton-windows have their own version numbers; compare by the Triton version they report.
  • The NVIDIA parts (triton.backends.nvidia, triton.language.extra.cuda) are copied into the wheel at build time from third_party/nvidia; in the repository they are not under python/triton. Reading the repository alone misses them, which is why this page reads the wheels.

How was this read, and how was it checked?

From the Python files that pip install triton puts on disk: for the first release of each minor version, the triton/**/*.py of the Linux x86_64 wheel on PyPI were read (by HTTP range requests, without downloading the whole wheel) and parsed with Python's ast module. A module's names are everything it binds at module level and what from .x import * brings in; code under if TYPE_CHECKING: is skipped. Dates come from PyPI. The PyTorch pins and PyTorch's has_triton_package() were read from the PyTorch wheels and metadata on PyPI; the bitsandbytes imports from its release tags.

Checks: (1) each of the 48 top-level names is found as plain text in triton/__init__.py in every release of its range (424 name-and-release pairs) and not on either side (10 edges). (2) A regular expression finds 10,635 definitions in 689 file versions; all are among the names read. (3) Against a different source, the triton git tags, 12 release checks agree:

Limits

  • Nothing was installed or run. "Has it" means the import statement resolves in the Python files; Triton's compiled extension (triton._C) is not read.
  • Only the first release of each minor version was read (and the newest). A change in a patch release is attributed to the next minor.
  • Only the Linux x86_64 wheel (CPython 3.12, or 3.11 for older releases) was read. Other wheels of the same release should carry the same Python files.

Questions

How do I fix "No module named 'triton.ops'"?

Triton 3.2.0 (2025-01-22) removed triton.ops; 3.1.0 is the last release with it. The import is usually in bitsandbytes: 0.45.0 and older import triton.ops.matmul_perf_model when Triton is installed, so import bitsandbytes fails on PyTorch 2.6 and later, which install Triton 3.2 or newer. Upgrade bitsandbytes to 0.45.1 or later. Pinning Triton below 3.2 would break PyTorch's own pin.

How do I fix "cannot import name 'libdevice' from 'triton.language.extra.cuda'"?

That path exists from Triton 3.0.0 (2024-07-19). The installed Triton is 2.x, usually because PyTorch is older than 2.4 (PyTorch 2.4.0 pins Triton 3.0.0). Upgrade PyTorch, which brings the matching Triton. In Triton 2.1 to 2.3 the same functions are in triton.language.math.

Why does PyTorch say "Cannot find a working triton installation" when Triton is installed?

PyTorch 2.6 to 2.8 check for Triton by importing triton_key from triton.compiler.compiler, which Triton 3.5.0 (2025-10-13) removed. With Triton 3.5 or newer next to PyTorch 2.8 or older, torch.compile thinks Triton is missing. Install the Triton that your PyTorch pins, or upgrade PyTorch (2.9.0 only imports triton).

Which Triton does my PyTorch need?

Each PyTorch wheel on PyPI pins one Triton release on Linux: 2.4.0 needs 3.0.0, 2.6.0 needs 3.2.0, 2.9.0 needs 3.5.0, and so on. The table on this page lists them from the PyPI metadata.

Does this page cover the backends and experimental modules too?

Yes: every module that the Triton wheel installs, 2.0.0 to 3.9.0, 5,531 module-and-name pairs in 187 modules, including triton.backends and triton.language.extra, which are copied in at build time and are not under python/triton in the repository.
