ImportError: cannot import name 'X' from 'langchain.chains', 'langchain.schema', 'langchain.chat_models' ...: which version has it, and where it is now

LangChain 1.0.0 (2025-10-17) removed 39 of its top-level modules, among them langchain.chains, langchain.schema, langchain.memory, langchain.llms and langchain.vectorstores; 0.3.30 is the last release with them. 38 of them live on under the same path in the separate package langchain-classic: pip install langchain-classic, then from langchain_classic.chains import LLMChain. Messages, documents and prompts are in langchain_core. Model classes such as ChatOpenAI are in the provider packages (langchain_openai). Many names under langchain.* in 0.1 to 0.3 were never defined there: they were forwarded to langchain_community and worked only with it installed. For any name, paste the error below.

Why did some imports work only with langchain-community installed?

In 0.1 to 0.3, modules such as langchain.chat_models, langchain.llms, langchain.vectorstores and langchain.document_loaders forwarded 1,243 names to langchain_community through a module-level __getattr__, with a deprecation warning. Without langchain-community the same line raised ImportError, on any version. langchain_classic keeps that forwarding. The lookup marks each forwarded name and gives the langchain_community module to import from directly.

How was this read, and how was it checked?

From the source of each release tag of the langchain monorepo, with Python's ast module; no release was installed or imported. langchain 0.x is read from libs/langchain, 1.x from libs/langchain_v1, langchain-classic from libs/langchain/langchain_classic, langchain-core from libs/core. A module's names are everything it binds at module level, plus the names its __getattr__ serves: the strings of __all__ and the keys of its lookup tables (DEPRECATED_LOOKUP, _dynamic_imports, create_importer(...)). Dates come from PyPI.

Checks, by a second reading: (1) each top-level name is found as plain text in __init__.py in every release of its range (8,586 name-and-release pairs). (2) A regular expression finds 29,928 definitions in 7,163 file versions; all are among the names read. (3) Regular expressions over every module that defines __getattr__ find 161,854 served names (summed over releases); all are among the names read. (4) 17 known facts hold, among them the reports under Sources.

Limits

  • Nothing was installed or run. "Has it" means the import resolves in the source, with langchain-community installed for forwarded names.
  • langchain 0.0.x is not read; "0.1.0 or earlier" means the name was there in the first release read. langchain-core is read from 0.1.47 (its first git tag), at the first release of each minor.
  • langchain_community and the provider packages (langchain_openai, ...) are not read; the lookup names them only where langchain itself points to them.
  • A forwarded name is taken from __all__; in 0.1 the forwarding passed along any name of the target module, so a few more names worked.

Questions

How do I fix "cannot import name 'LLMChain' from 'langchain.chains'"?

LangChain 1.0.0 (2025-10-17) removed langchain.chains; 0.3.30 is the last release with it. Install the package that keeps the old code: pip install langchain-classic, then from langchain_classic.chains import LLMChain. Or pin pip install "langchain<1.0.0".

Where did langchain.schema, langchain.memory and langchain.agents.AgentExecutor go?

To langchain-classic: 38 of the 39 top-level modules that LangChain 1.0 removed exist under the same path in langchain_classic. Messages, documents and prompts are also in langchain_core (langchain_core.messages, langchain_core.documents, langchain_core.prompts). For agents, LangChain 1.0 has langchain.agents.create_agent.

Why did "from langchain.chat_models import ChatOpenAI" work in 0.3 but not in 1.0?

In 0.1 to 0.3, langchain.chat_models did not define ChatOpenAI; it forwarded the name to langchain_community.chat_models with a deprecation warning, and only when langchain-community was installed. 1.0 dropped the forwarding. Use from langchain_openai import ChatOpenAI.

I installed langchain-classic and "from langchain_classic.document_loaders import PyPDFLoader" still fails. Why?

langchain_classic forwards document loaders, vector stores and other integrations to langchain_community, like langchain 0.3 did. Install langchain-community, or import from langchain_community.document_loaders directly.

What did langchain-core 1.0 remove?

The modules langchain_core.beta, langchain_core.graph_vectorstores, langchain_core.memory, langchain_core.pydantic_v1. Memory classes live in langchain_classic.memory; for pydantic_v1, import from pydantic directly.
