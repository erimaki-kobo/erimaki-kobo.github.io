How many tokens does Japanese cost? Characters per token for 18 LLM tokenizers

On Japanese Wikipedia text, current tokenizers fit 1.27 to 1.84 Japanese characters into one token. llm-jp-3.1 packs the most (1.84 characters per token), then Qwen3.5 (1.60), Gemma 3/4 (1.59) and Llama 4 (1.55); GPT-4o's o200k gets 1.27. GPT-4's older cl100k, still used by phi-4 and Granite 4.0, gets only 0.92, more tokens than characters. The often-quoted rule that Japanese costs two to three times as many tokens as English is out of date: on the Python tutorial, which exists in both languages, the Japanese text needs 1.01x to 1.40x the English token count on every tokenizer here except cl100k (1.74x).

Measured 2026-11-11 · 18 tokenizers from Hugging Face, counted with transformers.js 4.3.2 · the o200k and cl100k counts were checked against an independent implementation (gpt-tokenizer 4.1.2) and matched exactly · 697,000 Japanese characters in three corpora

Count the tokens in your own Japanese text

Your text never leaves the browser. Each tokenizer's tokenizer.json is downloaded from Hugging Face the first time you use it (sizes shown), and the counting library is downloaded from jsDelivr and run only if its SHA-256 matches. Counts exclude special tokens such as BOS and chat-template markup, and each line is counted separately, as in the table.

Which tokenizers improved on Japanese, and by how much?

cl100k is the only tokenizer here that needs more tokens than characters. The three best multilingual tokenizers all have 200,000 to 270,000 entries, but size alone does not decide it: o200k also has 200,000 and sits near the bottom. llm-jp-3.1 is the exception: a 100,000-entry Unigram vocabulary built for Japanese and English, which beats every multilingual tokenizer on Japanese while staying close to them on English (62,814 tokens for the English tutorial, against 58,759 to 66,339 for the others).

  • Qwen3.5 moved from Qwen3's 152k vocabulary to 248k and needs 15% fewer tokens on Japanese Wikipedia text, with English almost unchanged.
  • Llama 4 needs 11% fewer tokens than Llama 3 on the same text.
  • Japanese models built by continued pretraining on Llama 3 keep its tokenizer: Llama-3.3-Swallow counts exactly like Llama 3.1.
  • o200k (GPT-4o) needs 27% fewer tokens than cl100k (GPT-4) on Japanese Wikipedia text.

FAQ

How many tokens is one Japanese character?
With current tokenizers, about 0.54 to 0.79 tokens per character on encyclopedic Japanese (1.3 to 1.8 characters per token). GPT-4o's o200k gives about 0.79 tokens per character on Japanese Wikipedia text; GPT-4's older cl100k gives about 1.09, more tokens than characters.
Which tokenizer is most efficient for Japanese?
Of the 18 measured, llm-jp-3.1 (a Japanese-first tokenizer) packs the most Japanese per token, 1.84 characters per token on Wikipedia text. Among multilingual models, Qwen3.5, Gemma 3/4 and Llama 4 are close behind at 1.55 to 1.60. GPT-4o's o200k and Mistral's Tekken are at 1.27.
Is Japanese still 2 to 3 times more expensive than English in tokens?
Not with current tokenizers. On the Python tutorial, where the same text exists in both languages, the Japanese version needs 1.01x to 1.40x the English token count on every tokenizer measured except GPT-4's cl100k (1.74x). The documentation shares code and markup between the two languages, which narrows the gap; prose without code would show a larger one.
Does Qwen3.5 use fewer tokens for Japanese than Qwen3?
Yes. Qwen3.5's new 248k vocabulary needs about 15% fewer tokens than Qwen3 on Japanese Wikipedia text (268,797 vs 317,354), while English stays almost the same.
Can I count tokens for Claude here?
No. Anthropic does not publish its tokenizer; use the token counting endpoint of the Claude API for exact counts.

How was this measured?

  1. Each tokenizer was loaded from its Hugging Face repo with transformers.js 4.3.2 in Chrome on 2026-11-11.
  2. Each non-empty line of a corpus was encoded separately without special tokens, and the counts were summed. Characters are Unicode code points, newlines excluded.
  3. As a cross-check, the o200k and cl100k results were recomputed with gpt-tokenizer 4.1.2, an independent JavaScript implementation of OpenAI's tokenizers, and matched to the token on all four corpora. Three tokenizers were also recounted with transformers.js 3.8.1 on the Wikipedia corpus with identical results.

Limitations

  • Claude, Gemini and other closed models are not included because their tokenizers are not published.
  • Counts depend on the text. Casual chat, legal text or text with many numbers will give different ratios; use the counter above on your own text.
  • Chat templates add a fixed number of tokens per message that are not counted here.
  • Tokenizers were loaded from each repo's current files on 2026-11-11. A repo that changes its tokenizer later will give different numbers.
