opencv-python 5.0 (2026-07-02) no longer has cv2.CascadeClassifier, cv2.HOGDescriptor, cv2.ml or cv2.gapi: opencv-contrib-python 5 still has them, and pip install "opencv-python<5" keeps them. OpenCV 5 also removed cv2.dnn.readNetFromCaffe, readNetFromDarknet and readNetFromTorch (5.0) and readNetFromTensorflow (5.1.0, 2026-11-17): load an ONNX model, or stay below 5. cv2.xfeatures2d, cv2.face, cv2.ximgproc and cv2.legacy have only ever been in opencv-contrib-python. 4.7.0 removed cv2.aruco.Dictionary_get (use getPredefinedDictionary); 4.5.1 moved cv2.TrackerMOSSE_create to cv2.legacy. How was this measured?

Every release of opencv-python-headless (37) and opencv-contrib-python-headless (44) on PyPI from 3.4.8.29 to 5.1.0.95 that is not yanked and has a wheel for Python 3.8 (cp38 or abi3) was installed in its own environment, and the names of cv2, of every submodule reachable from it, and of every class it defines were listed with dir(). The binding is a compiled extension module, so dir() lists every name it has; OpenCV raises no Python deprecation warnings, so there is no "warns" state. Python 3.8.20 and numpy 1.24.4 in every environment. 4.0.0 to 4.1.1 have wheels only up to Python 3.7 and were not installed, so a name that the 3.4 line has and 4.1.2.30 does not is reported as "not in 4.1.2.30", not as removed in a particular 4.0 or 4.1 release.

The headless packages are the same build without a GUI backend. Compared at 5.1.0.95 (both packages) and 4.6.0.66 (contrib), opencv-python and opencv-contrib-python have the same names plus cv2.qt. "OpenCV's own text" is the @deprecated line of the function's docstring in the last release that has it. import cv2.<name> was tried for each file in the package folder, each in its own process.

Questions

How do I fix "module 'cv2' has no attribute 'CascadeClassifier'"?

opencv-python 5.0.0.93 (2026-07-02) is the first release without cv2.CascadeClassifier; 4.14.0.94 is the last with it. opencv-contrib-python 5 still has it, and in 5.1.0.95 only the contrib package ships haarcascade_frontalface_default.xml in cv2.data. Either pip uninstall opencv-python and pip install opencv-contrib-python, or pip install "opencv-python<5". The same holds for cv2.HOGDescriptor, cv2.ml (SVM, KNearest) and cv2.gapi.

How do I fix "module 'cv2.dnn' has no attribute 'readNetFromCaffe'" (or readNetFromDarknet, readNetFromTensorflow)?

OpenCV 5.0.0.93 removed readNetFromCaffe, readNetFromDarknet and readNetFromTorch; 5.1.0.95 (2026-11-17) removed readNetFromTensorflow. In 5.1.0, cv2.dnn.readNet on a .caffemodel raises "Caffe importer has been removed" and asks for an ONNX-converted model or an older OpenCV. readNetFromONNX, readNetFromTFLite and readNet are still there. To keep the old readers: pip install "opencv-python<5".

How do I fix "module 'cv2' has no attribute 'xfeatures2d'" (or 'face', 'ximgproc', 'legacy', 'bgsegm')?

These modules have only ever been in opencv-contrib-python, in every release read (3.4.8.29 to 5.1.0.95). Uninstall opencv-python (and opencv-python-headless) and install opencv-contrib-python: one OpenCV package per environment. SIFT needs no contrib: cv2.SIFT_create is in opencv-python from 4.4.0.46. cv2.xfeatures2d.SURF_create exists in the contrib wheels but raises "This algorithm is patented and is excluded in this configuration" (tried in 4.14.0 and 5.1.0).

How do I fix "module 'cv2.aruco' has no attribute 'Dictionary_get'" (or 'DetectorParameters_create')?

opencv-contrib-python 4.7.0.68 (2022-12-30) removed them; 4.6.0.66 is the last with them. Use cv2.aruco.getPredefinedDictionary(cv2.aruco.DICT_4X4_50), cv2.aruco.DetectorParameters(), and cv2.aruco.ArucoDetector(dictionary, parameters).detectMarkers(image). drawMarker became generateImageMarker, CharucoBoard_create became CharucoBoard((squaresX, squaresY), squareLength, markerLength, dictionary). opencv-python has cv2.aruco only from 4.7.0.72. OpenCV 5.0 then removed the cv2.aruco.detectMarkers function and estimatePoseSingleMarkers (OpenCV's text: "Use cv::solvePnP").

How do I fix "module 'cv2' has no attribute 'TrackerMOSSE_create'" (or 'MultiTracker_create')?

opencv-contrib-python 4.5.1.48 (2021-01-02) moved the MOSSE, Boosting, MedianFlow and TLD trackers and MultiTracker to cv2.legacy: cv2.legacy.TrackerMOSSE_create(), cv2.legacy.MultiTracker_create(). They were never in opencv-python. TrackerKCF_create and TrackerCSRT_create are at the top level of the contrib package in every release; TrackerMIL_create is in opencv-python from 4.5.1.48.

What does "ImportError: Bindings generation error. Submodule name should always start with a parent module name. Parent name: cv2.cv2" mean?

import cv2.cv2 (an old trick for editor completion) works up to 4.5.5.64 and raises this error in every release from 4.6.0.66. In the 3.4 line it works up to 3.4.17.63; 3.4.18.65 raises "No module named 'cv2.cv2'; 'cv2' is not a package". Write import cv2.

How do I fix "module 'cv2.gapi.wip.draw' has no attribute 'Text'" or "module 'cv2.dnn' has no attribute 'DictValue'"?

Both names are read by cv2/typing/__init__.py, which the packages ship from 4.8.0.76. Every clean install here imported without error. The first error appeared in each of four tries where a newer opencv-python-headless (4.8.0.76, 4.8.1.78, 4.9.0.80) and then an older opencv-contrib-python-headless (4.5.4.58 to 4.5.5.64) were installed into one environment: the newer package's cv2/typing folder stays behind and the older one loads it. The second error did not appear in those tries; it comes from the same file. pip uninstall all four packages (opencv-python, opencv-contrib-python and the two -headless ones), then install exactly one.
