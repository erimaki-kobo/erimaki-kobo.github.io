ImportError: cannot import name 'X' from 'gradio' (inputs, Box, IOComponent, ChatInterface, ...): which releases have it

Most of these errors come from gradio 4.0.0 (2023-10-31), which removed gr.inputs, gr.outputs, Box, Carousel, Variable, StatusTracker, interpretation and 13 more top-level names, and IOComponent from gradio.components; 3.50.2 is the last release that has them. Replace gr.inputs.Textbox(...) with gr.Textbox(...) (the same for every input and output class), Variable with State and Carousel with Gallery. To run old code unchanged, pin pip install "gradio<4.0.0"; on a Hugging Face Space the gradio version comes from sdk_version in the Space's README.md. The opposite error, a new name on an old gradio, means upgrading: ChatInterface needs 3.37.0, ChatMessage 4.38.0. For any other name, in any module of gradio, paste the error below.

What did gradio 4.0.0 remove, and what replaces each name?

These 21 names left from gradio import ... (and gr.X) in 4.0.0, together with gradio.components.IOComponent. Where gradio named a replacement, it is quoted from the deprecation messages of 3.50.2; the lookup shows the same hints.

Removed in 4.0.0Use instead
gr.inputsthe components themselves: gr.Textbox(), gr.Image() and so on. gradio 3.50.2 said: "Usage of gradio.inputs is deprecated, and will not be supported in the future, please import your component from gradio.components".
gr.outputsthe components themselves (gr.Textbox(), gr.Label(), ...); gradio.outputs was deprecated in 3.50.2 like gradio.inputs.
gr.Boxno named replacement; 3.50.2 marks Box "DEPRECATED". gr.Group() or gr.Column() are the layouts that remain.
gr.Carouselgr.Gallery(). gradio 3.50.2 said: "The Carousel component is deprecated. Please consider using the Gallery component".
gr.Variablegr.State(). gradio 3.50.2 said: "Variable was renamed to State".
gr.StatusTrackernothing; it was deprecated in 3.50.2 and removed.
gr.Webcamgr.Image(sources=["webcam"]) (4.0.0 renamed source to sources).
gr.Interpretationnothing; gradio 4.0.0 removed interpretation.
gr.interpretationnothing; gradio 4.0.0 removed interpretation.
gr.Parallelnothing in gradio; Parallel and Series (gradio.mix) were removed in 4.0.0.
gr.Seriesnothing in gradio; Parallel and Series (gradio.mix) were removed in 4.0.0.
gradio.components.IOComponentgradio.components.Component (custom components subclass it from 4.0.0).

gradio 5.0.0 (2024-10-09) removed make_waveform and HuggingFaceDatasetSaver (and LogoutButton) from the top level; 4.44.1 is the last release with them.

How do I read the error?

  • On a Hugging Face Space, the gradio version is the sdk_version in the Space's README.md, not what requirements.txt says. A Space that stopped working after a rebuild usually got a newer gradio there.
  • The path in parentheses is the copy of gradio that was imported. If it points into your project (a file named gradio.py), rename yours.
  • The module after "from" decides which table applies: from 'gradio' is the top level, from 'gradio.components' that module. When the import is in another package (an extension or an old app template), upgrade or pin gradio to the range that package was written for.

How was this read, and how was it checked?

From the source of each release, with Python's ast module; no release was installed or imported. gradio's git tags (gradio@X.Y.Z) start at 3.41.0; for 3.0 to 3.40 the package files were read from the wheels on PyPI (only the needed parts of each wheel, by HTTP range requests). gradio imports eagerly, so a module's names are everything it binds at module level: classes, functions, assignments, imports, and what from .x import * brings in. Code under if TYPE_CHECKING: is skipped. Dates come from PyPI.

Checks, by a second reading of the same files: (1) each of the 236 top-level names read from the git tags is found as plain text in __init__.py (or the modules it star-imports) in every release of its range (26,624 name-and-release pairs with the wheel part), and is not imported there in the release on either side (128 edges). (2) A regular expression finds 29,937 definitions in 3,331 file versions; all are among the names read. Limits

  • Nothing was installed or run. "Has it" means the import statement resolves in the source.
  • Only the first release of each minor version was read (and the newest). A name added in a patch release is attributed to the next minor; a name removed in a patch release shows its removal one minor later.
  • Releases before 3.0.1 are not covered.
  • Errors that are not about import names, such as a component argument that was renamed (source to sources in 4.0.0), are not covered.

Questions

How do I fix "cannot import name 'inputs' from 'gradio'" (or 'outputs')?

gradio 4.0.0 (2023-10-31) removed gradio.inputs and gradio.outputs; 3.50.2 is the last release with them. Replace gr.inputs.Textbox(...) with gr.Textbox(...), gr.outputs.Label(...) with gr.Label(...), and so on, as the 3.50.2 deprecation message said. To run the old code unchanged, pin pip install "gradio<4.0.0"; on a Hugging Face Space, set sdk_version in README.md.

How do I fix "cannot import name 'IOComponent' from 'gradio.components'"?

IOComponent was removed in gradio 4.0.0 (3.50.2 is the last release with it). Code that subclasses it, usually a custom component or an old extension, has to subclass gradio.components.Component instead, or pin gradio<4.0.0.

Why does "from gradio import ChatInterface" fail?

Your gradio is older than 3.37.0, the first release (of each minor version read) that has ChatInterface. Upgrade gradio. The same holds for ChatMessage (4.38.0), Sidebar (5.14.0) and the other names in the table of additions.

gradio fails with "cannot import name 'HfFolder' from 'huggingface_hub'". Is that gradio's fault?

It is the combination: gradio 4.9.0 to 5.7.x import HfFolder, which huggingface_hub 1.0.0 removed. Upgrade gradio to 5.8.0 or later, or pin huggingface_hub below 1.0.0. The huggingface_hub page on this site has the details.
