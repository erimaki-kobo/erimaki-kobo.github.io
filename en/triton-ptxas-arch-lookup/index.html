Answers for LLM inference engineers · Triton 3.0.0 to 3.9.0, PyTorch 2.4.0 to 2.15.0, vLLM 0.5.4 to 0.34.0, CUDA 12.0 to 13.5 · published 2026-11-16

ptxas fatal: Value 'sm_121a' is not defined for option 'gpu-name': which Triton, PyTorch and vLLM release fixes it

Short answer: the ptxas inside your Triton wheel is older than your GPU. The bundled binary knows RTX 50 (sm_120a) from Triton 3.3.0 (PyTorch 2.7.0, vLLM 0.9.0), DGX Spark (sm_121a) and B300 (sm_103a) from Triton 3.6.0 (PyTorch 2.10.0, vLLM 0.17.0), and Jetson AGX Thor (sm_110a) from Triton 3.7.0 (PyTorch 2.12.0, vLLM 0.27.0). On an older release you can point Triton at a newer ptxas, but the variable is not always TRITON_PTXAS_PATH: from Triton 3.6.0 these GPUs use a second binary whose variable is TRITON_PTXAS_BLACKWELL_PATH, and a path that does not exist is ignored without a message.

Six ways the usual advice fails

  1. TRITON_PTXAS_PATH is the wrong variable for Blackwell on Triton 3.3.x and from 3.6.0. Those releases ship two binaries and run ptxas-blackwell for compute capability 10.0 and up (9.0 and up in 3.9.0). If the error line starts with ptxas-blackwell fatal, this is your case. Set TRITON_PTXAS_BLACKWELL_PATH.
  2. On Triton 3.3.0 and 3.3.1 (PyTorch 2.7.x) that variable is spelled TRITON_PTXAS-BLACKWELL_PATH. The name is built with binary.upper(), which keeps the hyphen, and bash export does not accept a hyphen. Use env 'TRITON_PTXAS-BLACKWELL_PATH=/usr/local/cuda/bin/ptxas' python ..., set it through os.environ before importing triton, or replace triton/backends/nvidia/bin/ptxas-blackwell with a symlink. Triton 3.6.0 converts the hyphen to an underscore.
  3. A path that does not exist is skipped silently. In every release, if the file the variable names is not there, Triton uses the bundled binary and prints nothing. Inside a container /usr/local/cuda/bin/ptxas is often absent, because runtime-only CUDA images do not include the compiler. The error then looks exactly as before. The Repro command: line in the traceback (Triton 3.2.0 and newer) shows which file was run.
  4. Old Triton rejects new CUDA numbers. Triton reads the override's --version and maps it to a PTX version. Triton 3.2.0 (PyTorch 2.6.0) accepts nothing newer than CUDA 12.6, so no ptxas that knows a Blackwell GPU is usable with it. Triton 3.3.0 to 3.4.0 accept CUDA 12.x only, so a CUDA 13 ptxas raises Triton only support CUDA 10.0 or higher, but got CUDA version: 13.x. CUDA 13 is accepted from Triton 3.5.0. Jetson AGX Thor needs CUDA 13, so it has no fix below Triton 3.5.0.
  5. Triton 3.4.0 to 3.5.1 (PyTorch 2.8.0 to 2.9.1) went back to one binary. They ship only ptxas, the CUDA 12.8.93 build, for every GPU. That build knows sm_120a but not sm_121a, sm_103a or sm_110a. Here TRITON_PTXAS_PATH is the right variable.
  6. TORCH_CUDA_ARCH_LIST does nothing for this error. Triton builds the name from the device's compute capability (major * 10 + minor, plus a for 9.0 and up from Triton 3.3.0). There is no setting that makes it pass sm_120a on an sm_121 device.

Arm machines (DGX Spark, Jetson AGX Thor): PyPI has aarch64 Triton wheels from 3.5.0 only. The Triton requirement in PyTorch's PyPI metadata is limited to x86_64 up to 2.10.0 and applies to every Linux machine from 2.11.0. CUDA builds of PyTorch for Arm often come from another index, which was not read here. On Arm, check triton.__version__ directly instead of inferring it from PyTorch.

How this was checked, and what was not

  • Bundled binaries: every Triton wheel on PyPI from 3.0.0 to 3.9.0 (x86_64, and aarch64 where it exists) was downloaded, verified against the sha256 PyPI publishes, and bin/ptxas and bin/ptxas-blackwell were read for their version banner and for the sm_* names they contain. From Triton 3.3.0 each bundled file is byte-identical to the ptxas in NVIDIA's own nvidia-cuda-nvcc wheel of the same version.
  • ptxas releases: the same reading for every nvidia-cuda-nvcc-cu12 and nvidia-cuda-nvcc wheel on PyPI, CUDA 12.0 to 13.5, both architectures. Patch releases of one minor version list the same names.
  • Rules: which binary runs, how the name is built, the variable names, the fallback and the accepted CUDA numbers were read from third_party/nvidia/backend/compiler.py and python/triton/knobs.py at each release tag.
  • Not run. No ptxas was executed and nothing here was tested on a GPU. "Knows the name" is necessary for the compile to succeed, not sufficient: an override can get past this error and still fail later, most likely on Triton 3.2.0 and older, whose LLVM predates these GPUs.
  • Not covered: PyTorch wheels from download.pytorch.org (their Triton pin was not read), Triton built from source, triton-windows, and nightly builds.

Questions

What does "Value 'sm_121a' is not defined for option 'gpu-name'" mean?

Triton compiles its kernels by running NVIDIA's ptxas with --gpu-name=sm_NNNa, where NNN is your GPU's compute capability. The ptxas that ships inside the Triton wheel is a fixed CUDA build, and that build is older than your GPU. DGX Spark (12.1) needs a ptxas from CUDA 12.9 or newer, Jetson AGX Thor (11.0) from CUDA 13.0 or newer, RTX 50 (12.0) from CUDA 12.8 or newer.

Why does TRITON_PTXAS_PATH have no effect?

Three reasons, by release. In Triton 3.3.x and from 3.6.0 on, Blackwell GPUs use a second binary, ptxas-blackwell, and its variable is TRITON_PTXAS_BLACKWELL_PATH (in 3.3.x the name is TRITON_PTXAS-BLACKWELL_PATH, with a hyphen). In every release, a path that does not exist is skipped without a message and the bundled binary is used. And Triton 3.2.0 rejects any ptxas newer than CUDA 12.6, while Triton 3.4.0 and older reject CUDA 13.

Does TORCH_CUDA_ARCH_LIST change the name Triton passes to ptxas?

No. Triton asks for the compute capability of the current device and builds the name from it. TORCH_CUDA_ARCH_LIST is a build-time setting for compiling PyTorch and extensions.

Why does my error say sm_120 without the trailing a?

That is Triton 3.2.0 or older, which PyTorch 2.6 and older pin. Those releases add the a only for 9.0. Their bundled ptxas is CUDA 12.4, which knows nothing newer than sm_90a. Triton 3.3.0 (PyTorch 2.7.0) is the first that knows RTX 50.
