Answers for LLM inference engineers

vLLM batch invariance: what still breaks determinism, and how to test your endpoint

VLLM_BATCH_INVARIANT=1 makes a dense model on one GPU reproducible at temperature 0. It does not yet cover everything people run in production. As of November 2026, vLLM issues report divergence with the flag set for fused MoE experts with online FP8, MLA models under chunked prefill, AWQ models in compiled mode, and (on v0.29.0) tensor parallelism combined with sequence parallelism. Speculative decoding is outside the guarantee, and two newer model families refuse to start with the flag. The table below lists each case with its issue number. The tool underneath checks your own endpoint from the outside: it varies load, batch composition and prefix-cache state, and can compare two servers token by token.

Test your own endpoint

The test is black-box: it only needs the OpenAI-compatible API, so it works the same way whether the server runs TP, an MoE model or speculative decoding. Requests go straight from this page to the URL you enter.

A network error means the server does not accept cross-origin requests from this page, or it is a plain http:// host other than localhost (browsers block that from an HTTPS page). vLLM allows all origins by default. Otherwise use the command-line script, which has no such limits.

What do the four probes measure?

ProbeWhat it sendsWhat a difference means
baselineThe prompt N times, one request at a time. The most common output becomes the reference.Not reproducible even alone: shared endpoint, mixed replicas, or non-greedy decoding.
loadThe same prompt N times at each higher concurrency level.The result depends on batch size.
mixedThe same prompt N times, interleaved with three times as many other prompts of six different lengths.The result depends on what else is in the batch, not only how much. This is the case behind the MoE FP8 and AWQ reports.
cacheA prompt with a random session id, so its prefix cannot be cached, sent once cold and twice more warm. Eight such prompts.A cache hit takes a different numeric path than a full prefill.
abFour prompts (the default, a two-character one, a repetitive one and a long one) twice on each of two endpoints.The two deployments are not interchangeable: speculative decoding on versus off, TP 1 versus TP 4, eval server versus production, old version versus new.

Every comparison is made on tokens and, when the server returns them, on the logprob of each generated token. Identical tokens with different logprobs is a finding: the numerics already vary, and the text has not changed only because no near-tie was hit. Several of the issues above were first seen that way.

How do I read the verdict?

No divergence observed
Every completion matched the baseline in tokens and logprobs. That is evidence, not proof. In the Thinking Machines experiment the first 102 tokens of 1,000 completions were identical, so use long outputs and your real peak concurrency before relying on a clean result.
Logprob drift
Tokens matched but logprobs moved in at least one probe. The server is not invariant under that condition. Expect token flips on other prompts or longer outputs.
Token divergence
The generated text changed in the probes listed. The report shows the earliest split and the logprob gap between the top two candidates there. A gap of a few thousandths of a nat is a near-tie tipped by rounding. A large gap points at something structural, such as a different quantization scale or a different kernel.
Nondeterministic at baseline
Outputs differ for identical sequential requests. Fix or explain this first; the other probes cannot be interpreted until the baseline is stable.

Run it from the command line or in CI

detcheck.py is the same test as one Python file with no dependencies (standard library, Python 3.8+). Exit status is 0 when nothing diverged, 1 when tokens diverged, 3 when only logprobs drifted and 2 when it could not run, so it can gate a deployment.

curl -O https://erimaki-kobo.github.io/en/llm-determinism-test/detcheck.py

# all probes against a local server, model auto-detected
python detcheck.py --base-url http://localhost:8000/v1

# is the server with speculative decoding equivalent to the one without?
python detcheck.py --base-url http://localhost:8000/v1 --against http://localhost:8001/v1

# more thorough, with a JSON report
python detcheck.py --base-url http://localhost:8000/v1 --runs 64 \
  --concurrency 1,8,32,64 --max-tokens 500 --json report.json

Why does the same prompt give different outputs at temperature 0?

Temperature 0 makes token selection deterministic, not the logits. Floating-point addition is not associative, and GPU kernels for matrix multiplication, normalization and attention choose their reduction strategy from the tensor shape. The shape depends on the batch, and the server builds batches from whatever is in flight. Same request, different batch, slightly different logits. At a near-tie the argmax flips, and from that token on the two generations are different texts.

Thinking Machines Lab measured this in September 2025: 1,000 completions of one prompt at temperature 0 on Qwen3-235B produced 80 distinct outputs, with the first 102 tokens identical in all of them. With batch-invariant kernels for RMSNorm, matrix multiplication and attention, all 1,000 were identical. vLLM shipped that idea as VLLM_BATCH_INVARIANT=1.

Batch size is only one axis. The reports in the table add four more: the content of the neighbours (one activation scale shared by a whole batch), cache state (one-token prefill versus full prefill), how a prompt is chunked, and how many tokens the model verifies at once under speculative decoding. A fixed seed helps with none of them: at temperature 0 there is no sampling left for it to control.

How do I make inference deterministic?

  1. Turn the flag on: VLLM_BATCH_INVARIANT=1 vllm serve <model>. For an online server this is the only supported route; VLLM_ENABLE_V1_MULTIPROCESSING=0 applies to offline use. The feature is in beta, and reproducibility is promised only on the same hardware and the same vLLM version.
  2. Check your configuration against the table. If you run online FP8 on an MoE model, AWQ in compiled mode, MLA with chunked prefill, or sequence parallelism, the flag alone was not enough on the versions reported.
  3. Run the probes before and after. A clean dense-model result does not transfer to your MoE or TP deployment.
  4. Treat speculative decoding as a different deployment. Run the A/B probe against a server without it. If the outputs differ, evals taken on one do not describe the other.
  5. If you cannot get invariance (hosted API, unsupported model): compare outputs semantically instead of byte for byte, cache responses you need to replay, and report evals as a mean over several runs.

Other engines: SGLang has --enable-deterministic-inference, which was bit exact in the cold-versus-warm test in #40896; the LLM-42 paper measured its overhead at up to 56%. A server that processes one request at a time has no batch to vary and should pass the load and mixed probes.

What can this test not tell you?

  • It cannot prove determinism, only fail to find a counterexample.
  • It cannot say which kernel is responsible. It tells you which condition (load, neighbours, cache, deployment) changes the output; the issue threads above show how to bisect from there.
  • It measures the endpoint as deployed. Load balancers and replicas with different GPUs show up as baseline nondeterminism. A changing system_fingerprint is flagged when the server returns one.
  • On a shared endpoint "one request at a time" is not a batch of one, because other tenants fill the batch.
  • The cache probe assumes the server caches prefixes automatically. On a server without a prefix cache it simply passes.
  • The tool has been verified against a mock OpenAI-compatible server with one mode per failure type (load, logprob drift, content-dependent batches, cold versus warm, random, a differing second endpoint, no logprobs). It has not yet been run against a GPU server for this page. If a real server's response format differs, you will see request errors, not a wrong verdict.

Related tools

  • infer-check: pip-installable CLI with determinism and stress commands plus quantization sweeps and cross-backend diffs.
  • detLLM: in-process run-to-run and batch-size checks for Hugging Face models, with a repro pack.
  • vLLM's own suite under tests/ (needle, bs1_vs_bsN, chunked prefill, decode versus prefill logprobs) is white-box and the right tool once you are bisecting inside the engine.

Questions

Does temperature 0 guarantee the same output every time?

No. Temperature 0 means the server picks the highest-scoring token. The scores can change by tiny amounts when the batch, the cache state or the decoding path changes, and a tiny change at a near-tie picks a different token.

Is VLLM_BATCH_INVARIANT=1 enough to make vLLM deterministic?

For a validated dense model on one supported GPU, yes, on the same hardware and vLLM version. As of November 2026 it is not enough for speculative decoding, MoE experts quantized online to FP8, MLA models under chunked prefill, or AWQ models in compiled mode on the versions where those were reported, and some newer models refuse to start with the flag.

Does speculative decoding change the output at temperature 0?

It can. The algorithm is lossless in exact arithmetic, but the verify pass processes several tokens at once while plain decoding processes one, and vLLM does not guarantee the two produce identical bits (issue #54506). Compare a server with speculative decoding against one without, using the A/B probe.

Why does the first request after a restart differ from later identical requests?

Prefix caching. The first request computes the whole prompt; later ones reuse cached keys and values and compute only the tail, which is a different numeric path. Disabling prefix caching or enabling batch-invariant mode removed the difference in the reports cited above.

How many requests do I need?

Start with the defaults: 32 per level and 200 tokens. If that is clean, raise max_tokens to 500 or 1,000 and set the top concurrency level to your real peak. Longer outputs matter more than more requests, because every generated token is another chance to hit a near-tie.

Does this page see my API key or prompts?

No. The page is static. Requests go from your browser directly to the base URL you enter, and nothing is stored or sent anywhere else.
