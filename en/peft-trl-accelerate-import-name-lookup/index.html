ImportError: cannot import name 'X' from 'peft', 'trl' or 'accelerate' (or their submodules): which releases have it

The library named after "from" is too old for the name, or too new because the name was removed. The common ones: trl removed DataCollatorForCompletionOnlyLM in 0.20.0 (use SFTConfig(completion_only_loss=True)), setup_chat_format in 0.26.0 (use clone_chat_template), and 33 top-level names in 0.29.0, PPOTrainer and ORPOTrainer among them, most of which were then importable from trl.experimental. peft removed prepare_model_for_int8_training in 0.10.0 (use prepare_model_for_kbit_training). accelerate.utils has is_npu_available only from 0.21.0, which is why an older accelerate breaks import peft. For any other name, in any module of the three libraries, paste the error below.

The import is inside another library. Which package do I change?

The one in quotes after "from". ImportError: cannot import name 'is_npu_available' from 'accelerate.utils' raised while running from peft import LoraConfig means peft needs a newer accelerate, not that peft is broken: upgrade accelerate to 0.21.0 or later. cannot import name 'PartialState' from 'accelerate' raised from inside transformers means the same for accelerate 0.17.0. How was this read, and how was it checked?

From the source of each release tag, with Python's ast module; no release was installed or imported. peft and accelerate import eagerly, so a module's names are everything it binds at module level (classes, functions, assignments, imports). trl replaces its packages with a lazy module from 0.8.0 on; for those, the names are the entries of the lazy table, each followed to the file it names. Code under if TYPE_CHECKING: is skipped. Dates and yanked releases come from PyPI.

Checks, all by a second reading: (1) trl's lazy packages repeat their names as plain imports for type checkers; 214 of 231 package-and-release pairs match exactly, and the rest differ by 9 names that trl lists in only one of the two places (the lookup follows the table, which is what runs). (2) Each of the 369 top-level names is found as plain text in __init__.py of every release in its range (7,221 name-and-release pairs), and is not imported there in the release on either side (353 edges). (3) A regular expression finds 30,884 definitions in 4,557 file versions; all are among the names read. (4) 18 known facts hold, among them the releases in the public error reports under Sources.

Limits

  • Nothing was installed or run. "Has it" means the import statement resolves in the source, with the optional packages installed.
  • Only the first release of each minor version was read (and the newest release). A change made in a patch release is attributed to the next minor. Releases on PyPI without a git tag were skipped: trl 0.9.2, so trl's 0.9 line is read at 0.9.3.
  • The import can still fail for another reason: the file that defines the name imports something your transformers does not have. That shows up as a second cannot import name ... from 'transformers'; see the related page below.

Questions

How do I fix "cannot import name 'DataCollatorForCompletionOnlyLM' from 'trl'"?

trl 0.20.0 (2025-07-29) removed it; 0.19.1 is the last release with it. Either pin pip install "trl<0.20.0", or drop the collator and set SFTConfig(completion_only_loss=True), which is what trl 0.19.0 told you to use.

Where did PPOTrainer, ORPOTrainer and the other trainers go in trl 0.29.0?

trl 0.29.0 (2026-02-25) removed 33 names from the top level. 30 of them were still importable from trl.experimental in 0.29.0, for example from trl.experimental.ppo import PPOTrainer; the full list is in the table on this page. Later releases removed some of the experimental modules as well, so the lookup also says whether each one is still there in 1.18.1.

How do I fix "cannot import name 'prepare_model_for_int8_training' from 'peft'"?

Use prepare_model_for_kbit_training, which peft has had since 0.4.0. peft 0.10.0 (2024-03-21) removed the int8 name; 0.9.0 is the last release with it.

I import from peft but the error says "cannot import name 'is_npu_available' from 'accelerate.utils'". Which package do I upgrade?

accelerate. The library in quotes after "from" is the one that lacks the name; the import that fails can sit inside another library. accelerate.utils has is_npu_available from 0.21.0 (2023-07-13), so pip install -U "accelerate>=0.21.0".

Does this page cover names below the top level, like trl.trainer.utils or accelerate.utils?

Yes. Every module of the three libraries is covered: 14,806 module-and-name pairs in all, read from peft 0.0.1 to 0.21.3 (23 releases); trl 0.2.0 to 1.18.1 (48 releases); accelerate 0.1.0 to 1.16.0 (51 releases).
