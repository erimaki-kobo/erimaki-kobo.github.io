ImportError: cannot import name 'compare_ssim' from 'skimage.measure' (or 'greycomatrix', TypeError: unexpected keyword argument 'multichannel', 'selem'): which scikit-image release removed it and what to use

scikit-image 0.18.0 (2020-12-15) removed compare_ssim, compare_psnr, compare_mse and compare_nrmse from skimage.measure: import structural_similarity, peak_signal_noise_ratio, mean_squared_error and normalized_root_mse from skimage.metrics. 0.19.0 removed rgb2grey (use rgb2gray), draw.circle (draw.disk) and morphology.watershed (segmentation.watershed). 0.20.0 (2023-02-28) removed greycomatrix (graycomatrix), skimage.morphology.selem, skimage.viewer, skimage.future.graph (now skimage.graph), and the arguments multichannel= (use channel_axis=) and selem= (use footprint=). If the error comes from a library you did not write, upgrade that library or pin scikit-image below the release that removed the name. Paste the error below for the release-by-release answer.

How was this measured?

Each of 22 scikit-image releases (0.16.2 to 0.26.0, patch releases included) was installed from PyPI in its own environment; the public names of 22 modules (skimage and its subpackages) were listed with dir(), and getattr or an import was run for the union of all 715 names in every release. Releases: 0.16.2, 0.17.1, 0.17.2, 0.18.0, 0.18.1, 0.18.2, 0.18.3, 0.19.0, 0.19.1, 0.19.2, 0.19.3, 0.20.0, 0.21.0 (Python 3.8); 0.22.0 (Python 3.9); 0.23.0, 0.23.1, 0.23.2, 0.24.0, 0.25.0, 0.25.1, 0.25.2 (Python 3.10); 0.26.0 (Python 3.11). 0.23.0 was yanked on PyPI and is included. Each ran with a NumPy of its time (NumPy 1.19.5 for 0.16.2 to 0.17.2; NumPy 1.21.6 for 0.18.0 to 0.18.3; NumPy 1.22.4 for 0.19.0 to 0.19.3; NumPy 1.24.4 for 0.20.0 to 0.21.0; NumPy 1.26.4 for 0.22.0 to 0.24.0; NumPy 2.2.6 for 0.25.0 to 0.25.2; NumPy 2.4.6 for 0.26.0) and with matplotlib installed. The 25 older releases on PyPI (0.7.2 to 0.16.1) have no wheel for Python 3.8 or later and were not installed, so a name removed before 0.16.2 is outside this page.

For the arguments, the parameters of every public function and class (460 in 0.26.0) were read with inspect.signature in each release, together with the deprecation wrappers scikit-image attaches to a function (deprecate_kwarg, deprecate_multichannel_kwarg, remove_arg, deprecate_parameter). An argument is listed when a release accepts it and a later one has neither the parameter, nor a wrapper for it, nor **kwargs. That rule was checked against real calls: 29 old-argument calls were run in every release, and whether each raised TypeError: ... unexpected keyword argument agreed with the rule in all 594 call-and-release pairs. Arguments passed by position, and arguments a function forwards through **kwargs, are not covered.

The names table keeps names in a module's __all__, submodule files, and anything scikit-image itself deprecated; helpers a module merely imported (np, warn) and the setup.py build files are left out.

Questions

How do I fix "cannot import name 'compare_ssim' from 'skimage.measure'"?

scikit-image 0.18.0 (2020-12-15) removed compare_ssim, compare_psnr, compare_mse and compare_nrmse from skimage.measure; 0.16.2 to 0.17.2 warn when they are called. Use from skimage.metrics import structural_similarity, peak_signal_noise_ratio, mean_squared_error, normalized_root_mse. On the same two images compare_ssim and structural_similarity returned the same number (run in 0.16.2 to 0.17.2). skimage.metrics is in every release from 0.16.2 on. From 0.20.0, structural_similarity on float images raises a ValueError unless you pass data_range= (data_range=1.0 for images scaled 0 to 1); up to 0.19.3 the same call ran without it.

How do I fix "TypeError: ... got an unexpected keyword argument 'multichannel'"?

scikit-image 0.20.0 (2023-02-28) removed the multichannel argument from 25 functions (gaussian, rescale, pyramid_gaussian, slic, hog, denoise_tv_chambolle and others); 0.19.0 to 0.19.3 accept it with a warning. Use channel_axis: multichannel=True becomes channel_axis=-1, and multichannel=False becomes channel_axis=None. Same output for each pair run: gaussian multichannel=True and channel_axis=-1 (0.19.0 to 0.19.3); gaussian multichannel=False and channel_axis=None (0.19.0 to 0.19.3); rescale multichannel=True and channel_axis=-1 (0.19.0 to 0.19.3); structural_similarity multichannel=True and channel_axis=-1 (0.19.0 to 0.19.3). channel_axis itself only exists from 0.19.0, so code that must run on both sides needs a version check. structural_similarity is a special case: it takes **kwargs, so from 0.20.0 multichannel=True is not rejected but ignored, and a color image then fails with "ValueError: win_size exceeds image extent" (run with a 32x32x3 image in 0.20.0 to 0.26.0). Pass channel_axis=-1 there too.

How do I fix "unexpected keyword argument 'selem'" or "No module named 'skimage.morphology.selem'"?

scikit-image 0.20.0 removed the selem argument from 51 functions (skimage.morphology, skimage.filters.rank and a few others), and the skimage.morphology.selem module; 0.19.0 to 0.19.3 accept both with a warning. Write footprint=... instead of selem=..., and import disk, ball and the other shapes from skimage.morphology (or skimage.morphology.footprints, there from 0.19.0). footprint= does not exist before 0.19.0.

How do I fix "module 'skimage.feature' has no attribute 'greycomatrix'"?

scikit-image 0.20.0 removed greycomatrix and greycoprops; 0.19.0 to 0.19.3 have both spellings and warn on the old one. Use graycomatrix and graycoprops (American spelling), which take the same arguments and gave the same matrix in 0.19.x. They exist from 0.19.0, so on 0.18 and older the grey spelling is the only one.

How do I fix "No module named 'skimage.viewer'" or "No module named 'skimage.future.graph'"?

scikit-image 0.20.0 removed both. skimage.future.graph moved to skimage.graph: from skimage import graph, then graph.rag_mean_color, graph.cut_normalized and the rest (same region graph for the same image in 0.19.3 and 0.20.0). skimage.viewer has no replacement inside scikit-image; its own message points to the visualization page of the user guide.

How do I fix "cannot import name 'circle' from 'skimage.draw'"?

scikit-image 0.19.0 (2021-12-03) removed draw.circle; 0.17.1 to 0.18.3 warn. Use draw.disk, which takes the center as one tuple: circle(r, c, radius) becomes disk((r, c), radius). Both gave the same pixels in 0.17.1 to 0.18.3. disk does not exist in 0.16.2.
