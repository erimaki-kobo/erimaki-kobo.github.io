vLLM compatibility matrix: which PyTorch, CUDA and NVIDIA driver each release needs

vLLM v0.33.0 (released 2026-11-01) pins torch==2.14.0, is built for CUDA 13.0 only, and needs NVIDIA Linux driver 580 or newer. Every PyPI wheel since v0.20.0 loads libcudart.so.13, although the install guide at each of those tags still names CUDA 12.9 as the default. On a driver older than 580, the newest release with a prebuilt CUDA 12 wheel is v0.32.0 (the +cu129 wheel with torch==2.13.0+cu129), and the newest release where a plain pip install vllm gives a CUDA 12 build is v0.19.1. --torch-backend=cu129 changes which PyTorch is downloaded. It does not change the vLLM wheel that PyPI serves.

Published 2026-11-11 · Data as of 2026-11-10 · 50 stable releases, v0.8.0 to v0.33.0 · Linux x86_64

Which vLLM release can my driver and GPU run?

Enter what nvidia-smi reports. The answer is the newest release that has a prebuilt wheel for that combination, with the command to install it. Python and glibc are optional filters.

Driver version only: nvidia-smi --query-gpu=driver_version --format=csv,noheader. The lookup runs in your browser on the table below; nothing is sent anywhere. It covers Linux x86_64 wheels from PyPI and from the vLLM GitHub releases. The glibc filter compares against the wheel's platform tag, which is what pip checks.

PyTorch pin
The torch== requirement in the published wheel's metadata. It equals requirements/cuda.txt at the release tag for all 50 releases.
PyPI wheel links
The CUDA runtime that the wheel's compiled extensions load: libcudart.so.12 or libcudart.so.13, read from the wheel itself. "Built with" is the CUDA version vLLM's build defaulted to at that tag (VLLM_MAIN_CUDA_VERSION). "Guide says" appears where the install guide at that tag names a different default.
Driver floor
NVIDIA's minimum Linux driver for that CUDA major: 525.60.13 for CUDA 12.x and 580 for CUDA 13.x (the first R580 release was 580.65.06). A new GPU can need a newer driver than this.
PyTorch on PyPI: CUDA
The CUDA version of the pinned PyTorch that PyPI serves. PyTorch's CUDA 12.6 builds stop at Hopper (9.0); CUDA 12.8 and newer builds include Blackwell (10.0, 12.0); CUDA 13 builds start at Turing (7.5).
Other CUDA wheels
+cuNNN wheels attached to the GitHub release, with the PyTorch they pin. Install one together with the PyTorch index of the same name, for example --extra-index-url https://download.pytorch.org/whl/cu129.
GPU targets
The compute capabilities requested for the x86_64 release build. vLLM compiles each kernel for its own subset, so a listed target means the wheel runs on that GPU, not that every kernel has a native build for it.
Docker tag suffixes
Suffixes of vllm/vllm-openai:v<version> on Docker Hub: "default" is the bare tag, "cu129" is :v<version>-cu129. The default image follows the PyPI wheel's CUDA major.

The same data as JSON: matrix.json.

When did vLLM change CUDA, PyTorch and GPU support?

  • v0.9.0 (2025-05-27): the PyPI wheel is built with CUDA 12.8 and the build targets include Blackwell (10.0). Capability 12.0 (RTX 50 series) is listed from v0.9.2.
  • v0.10.2 (2025-10-07): the pin moves to torch 2.8.0, the first pinned PyTorch whose PyPI build uses CUDA 12.8. Before that (torch 2.7.x, CUDA 12.6 on PyPI) a Blackwell GPU needed the cu128 PyTorch index.
  • v0.10.1.1: the last release with a +cu118 wheel (CUDA 11.8).
  • v0.20.0 (2026-04-27): the default build switches to CUDA 13.0 (commit 3ed5231c6, PR #39878). The PyPI wheel loads libcudart.so.13, torch 2.11.0 on PyPI is a CUDA 13.0 build, capability 7.0 leaves the build targets and the documented minimum becomes 7.5. CUDA 12.9 stays available as the +cu129 wheel and the -cu129 image.
  • v0.32.0 (2026-10-17): requires Python 3.11 or newer (v0.31.0 is the last release for Python 3.10; v0.11.0 the last for 3.9). It is the last release with a +cu129 wheel and -cu129 images.
  • v0.33.0 (2026-11-01): torch 2.14.0. CUDA 12.9 is removed from the release pipeline (commit 083d61622, PR #62575); the release notes say wheels and images are CUDA 13.0 only. PyTorch publishes no cu129 build of 2.14.0 either: its index has cu126, cu130 and cu132.

As of 2026-11-10 the GitHub release titled v0.33.0 is attached to the tag v0.33.0rc3, so the snippet in the install guide that builds a wheel URL from releases/latest produces a URL that does not exist. The wheels themselves are named vllm-0.33.0-....

What can I do if my NVIDIA driver is older than 580?

There are five routes. The first three keep the current driver.

  1. Pin v0.32.0 with the CUDA 12.9 wheel. It needs driver 525.60.13 or newer: 
    uv pip install "https://github.com/vllm-project/vllm/releases/download/v0.32.0/vllm-0.32.0+cu129-cp38-abi3-manylinux_2_28_x86_64.whl" --extra-index-url https://download.pytorch.org/whl/cu129
  2. Use the matching image: vllm/vllm-openai:v0.32.0-cu129.
  3. Data center GPUs on an R535 or R570 driver: NVIDIA's forward-compatibility package lets a CUDA 13.0 runtime run on those two branches. It applies to data center GPUs, select NGC Server Ready RTX cards and Jetson, not to GeForce cards. The vLLM images carry the compatibility libraries, and from v0.17.0 they are opt-in: the install guide enables them with --env VLLM_ENABLE_CUDA_COMPATIBILITY=1 on docker run.
  4. Update the driver to R580 or newer and install v0.33.0 normally.
  5. Build from source against a CUDA 12 PyTorch. The install guide covers it; this page does not.

How was this table checked?

  • PyTorch pin, Python range, wheel tag: PyPI metadata of each release, compared with requirements/cuda.txt and pyproject.toml at the release tag. They agree for all 50 releases.
  • CUDA of each wheel: the DT_NEEDED entries of the compiled extensions inside every published x86_64 wheel: 50 PyPI wheels and 63 +cuNNN wheels from GitHub releases. The linked libcudart major matches the build default in vllm/envs.py or setup.py at every tag.
  • CUDA of PyTorch on PyPI: the CUDA runtime packages that each pinned torch release depends on in its PyPI metadata.
  • PyTorch builds per CUDA version: the file list of the PyTorch wheel index.
  • Driver floors: NVIDIA's CUDA Toolkit release notes (12.x: 525 or newer, 13.x: 580 or newer). uv uses 525.60.13 and 580 for the same decision.
  • GPU targets: the architecture list in .buildkite/release-pipeline.yaml or docker/Dockerfile at each tag, and PyTorch's CUDA support matrix in its RELEASE.md.
  • Variant wheels and images: the GitHub releases API, the per-version indexes on wheels.vllm.ai and the Docker Hub tag list, all read on 2026-11-10.

What this page does not cover

  • Nothing was installed or run on a GPU for this page. The commands are assembled from the facts above and follow the forms in vLLM's install guide.
  • Linux x86_64 only. aarch64 wheels exist from v0.10.2 but were not inspected. Windows and WSL are not covered.
  • Docker images were not opened. Their CUDA version is taken from the release pipeline at each tag.
  • Nightly wheels, ROCm, CPU and XPU builds, and source builds are out of scope.
  • The table is regenerated when a new release appears; the "as of" date at the top says how current it is.

Questions

Which PyTorch version does vLLM 0.33.0 need?
torch==2.14.0. The pin is exact (==) in every release from v0.8.0 to v0.33.0; the table above lists each one. pip and uv will not install a prebuilt vLLM wheel next to any other PyTorch version.
Why does vLLM fail with "libcudart.so.13: cannot open shared object file"?
The vLLM wheel in the environment is a CUDA 13 build (every PyPI wheel from v0.20.0 on), but the installed PyTorch is a CUDA 12 build, so no CUDA 13 runtime library is present. It happens when --torch-backend=cu129, cu128 or cu126 is combined with the default wheel. On driver 580 or newer, install the default PyTorch. On an older driver, use the +cu129 vLLM wheel (v0.20.0 to v0.32.0).
Does --torch-backend=cu129 install a CUDA 12 build of vLLM?
No. The flag tells uv which PyTorch index to use for torch and its companion packages. The vLLM wheel still comes from PyPI, and from v0.20.0 that wheel is a CUDA 13 build. A CUDA 12 build of vLLM is a separate +cu129 wheel, published on the GitHub release and on wheels.vllm.ai for v0.20.0 to v0.32.0.
What is the newest vLLM I can install on an NVIDIA driver older than 580?
v0.32.0, using the +cu129 wheel with torch==2.13.0+cu129, on a Linux driver from 525.60.13 up. v0.33.0 has no CUDA 12 wheel or image. On data center GPUs with an R535 or R570 driver, the CUDA 13 Docker image can also run in NVIDIA's forward-compatibility mode.
Which vLLM versions support RTX 50-series GPUs (compute capability 12.0)?
The release build lists capability 12.0 from v0.9.2. PyTorch must be a CUDA 12.8 or newer build as well: that is what PyPI serves from v0.10.2 (torch 2.8.0). For v0.9.2 up to v0.10.1.1, add the cu128 PyTorch index.
Does vLLM still support the Tesla V100 (compute capability 7.0)?
Not after v0.19.1. v0.20.0 removed capability 7.0 from the build targets and raised the documented minimum to 7.5, and PyTorch's CUDA 13 builds start at Turing (7.5).
Can I use a different PyTorch version than the pinned one?
Not with the prebuilt wheels. vLLM's install guide says that a different CUDA version or an existing PyTorch installation requires building vLLM from source.
