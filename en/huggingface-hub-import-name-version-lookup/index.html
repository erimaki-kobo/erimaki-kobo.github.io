ImportError: cannot import name 'cached_download' (or HfFolder, or any name) from 'huggingface_hub': which releases have it

cached_download was removed in huggingface_hub 0.26.0 (2024-10-18); the last release that has it is 0.25.2. HfFolder, Repository and InferenceApi were removed in 1.0.0 (2025-10-27); the last release that has them is 0.36.2. The error means a library written for an older hub is running against a newer one. Fix it by upgrading that library (diffusers 0.29.0 or later and sentence-transformers 2.3.0 or later no longer import cached_download; gradio 5.8.0 or later and datasets 2.16.0 or later no longer import HfFolder), or by pinning the hub below the release that dropped the name: pip install "huggingface_hub<0.26.0" or "huggingface_hub<1.0.0". For any other name, paste the error below.

"At least" is the newest first-release among the names it imports; "below" is the first hub release that dropped one of them. The name in parentheses is the one that sets the limit. The range is about imports only: a library's own dependency declaration can be narrower, and pip follows that.

"0.28.x" means the 0.28 series. An import inside a try block, a function, if TYPE_CHECKING: or an if on the installed hub version (datasets 4.8.0 to 5.0.x) is not counted, because it does not stop the library from importing. All files of the package are counted, including ones a library loads only on demand (diffusers loads most pipeline files that way), so "at least" can be stricter than what a plain import of the library needs; "below" for cached_download and HfFolder is confirmed by the public error reports linked under Sources.

How do I read the error?

  • The traceback names the file that asked for the name, a few lines above the error. If it is inside site-packages/diffusers/, sentence_transformers/, gradio/ or another library, that library is older than your hub: upgrade it, or pin the hub.
  • The path in parentheses is the copy of huggingface_hub that was imported. Check that it is the version you expect: python -c "import huggingface_hub as h; print(h.__version__, h.__file__)".
  • On a Space, the hub version is whatever the Space's SDK and requirements.txt resolve to at build time, so an app that worked can break on a rebuild. Pin huggingface_hub in requirements.txt, or raise the pins of the libraries that import the old name.
  • "Did you mean: 'hf_hub_download'?" at the end is Python's spelling suggestion, not advice from the library; for cached_download it happens to name the real replacement.

How was this read, and how was it checked?

From the source of each release tag, with Python's ast module; no release was installed or imported.

  • huggingface_hub up to 0.7.x imports its names eagerly in __init__.py; from 0.8.1 the top level is lazy and serves the names of one table (_SUBMOD_ATTRS), which is read. The module-level __getattr__ has no other rule; the build stops if a release adds one.
  • huggingface_hub.utils and huggingface_hub.errors: the names the module binds, plus the lazy table of utils where it has one.
  • The five libraries: every .py file of the package at the first release of each minor version, looking for from huggingface_hub import ..., from huggingface_hub.utils import ... and from huggingface_hub.errors import ... at module level.
  • Dates and yanked releases come from PyPI. Where the .0 release of a minor version was yanked or never uploaded, the first release pip installs is used.

Checks, all by a second reading: (1) every lazy release carries a generated static copy of its table for type checkers; in all 66 lazy releases that have one, the copy and our reading are identical (66 of 66). (2) For each of the 8 "library imports a removed name" ranges, a plain-text search of the library's files finds the import at both ends of the range and no module-level import in the version after it. (3) 16 facts from deprecation messages and release notes hold (for example cached_download carries @_deprecate_method(version="0.26") in 0.25.0 and is gone in 0.26.0).

Limits

  • Nothing was installed or run. The library ranges say which hub releases let the library's files import; they do not say every feature works across that range.
  • Only the first release of each minor version was read, for the hub and for the libraries. A change made in a patch release is attributed to the next minor.
  • A module-level import in a file that the library itself only loads on demand does not break import library, only the feature that loads that file. The lookup names one such file per range in data.json.
  • Submodules of the hub other than utils and errors are not covered (huggingface_hub.constants, huggingface_hub.file_download, huggingface_hub.inference and so on), and libraries other than the five are not read.
  • "Instead" is given only where the hub's own deprecation message or docstring names a replacement.

Questions

Which huggingface_hub version removed cached_download?

huggingface_hub 0.26.0 (2024-10-18). cached_download is importable through 0.25.2. Its deprecation message names the replacement: hf_hub_download, which takes a repo id and a file name where cached_download took a URL.

How do I fix "cannot import name 'cached_download' from 'huggingface_hub'" with diffusers or sentence-transformers?

Upgrade the library that asks for it: diffusers imports cached_download at module level from 0.1.0 to 0.28.x and stops in 0.29.0, sentence-transformers from 2.0.0 to 2.2.x and stops in 2.3.0. If you cannot upgrade it, pin the hub instead: pip install "huggingface_hub<0.26.0" (0.25.2 is the last release that has the name).

Why can't I import HfFolder from huggingface_hub?

huggingface_hub 1.0.0 (2025-10-27) removed HfFolder; 0.36.2 is the last release that has it. Use login() to store a token and get_token() to read one. gradio imports HfFolder at module level from 4.9.0 to 5.7.x and stops in 5.8.0; datasets from 1.13.0 to 2.15.x and stops in 2.16.0.

How do I fix "cannot import name 'BucketNotFoundError' from 'huggingface_hub.errors'"?

BucketNotFoundError first appears in huggingface_hub 1.5.0 (2026-02-26). datasets 5.1.0 and later import it at module level and declare huggingface-hub>=1.31.0, so the error means the hub was kept older than 1.5.0, often below 1.0 for transformers 4.x. Upgrade the hub (pip install -U "huggingface_hub>=1.31.0"), or, if it has to stay on 0.x, use datasets 5.0.1: 4.8.0 to 5.0.1 import the name only when the installed hub is 1.6.0 or newer.

Does pinning huggingface_hub break anything else?

It can. Newer releases of the same libraries import names that old hub releases do not have: for example diffusers 0.33.0 and later need huggingface_hub 0.27.0 or newer for DDUFEntry. Pick a hub release inside the range of every library you have installed; the table on this page gives that range per library version.

The name in my error is not cached_download or HfFolder. Does this page cover it?

Yes. The lookup covers every name that huggingface_hub, huggingface_hub.utils and huggingface_hub.errors have exported from 0.0.1 to 2.4.0: 568 top-level names, of which 49 are gone from the newest release.
