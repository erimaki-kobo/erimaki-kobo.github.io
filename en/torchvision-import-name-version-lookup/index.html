No module named 'torchvision.transforms.functional_tensor', cannot import name 'read_video' (or any name) from 'torchvision...': which torchvision releases have it

torchvision 0.17.0 (2024-01-30) removed torchvision.transforms.functional_tensor (0.16.x is the last with it), and 0.26.0 (2026-03-23) removed video decoding (torchvision.io.read_video, VideoReader). The first breaks basicsr, and with it Real-ESRGAN and GFPGAN: change from torchvision.transforms.functional_tensor import rgb_to_grayscale to from torchvision.transforms.functional import rgb_to_grayscale, or pin torchvision<0.17. For video, use TorchCodec or pin torchvision<0.26. Each torchvision pins one torch release, so pinning torchvision pins torch too: the table below lists every pair. For any other name, paste the error below.

How was this read, and how was it checked?

From the Python files of the first release of every minor on PyPI, plus the latest, read from the Linux x86_64 wheels by HTTP range requests and parsed with Python's ast module. The wheels and the git tags of pytorch/vision agree except for the generated version.py and the prototype package noted above. A module's names are everything it binds at module level and what from .x import * brings in. From 0.26.0, torchvision/io/__init__.py imports the video API from pytorch.vision.fb, a Meta-internal package, inside try: ... except ImportError: pass; that package is not on PyPI, so those names are counted as absent, and torchvision.io.video from 0.28.0, which imports it unconditionally, is counted as not importable.

Checks: (1) the top-level names are found as plain text in torchvision/__init__.py in every release of their range (652 name-and-release pairs) and are not bound on either side (20 edges). (2) A regular expression finds 14,932 definitions in 1,706 file versions; all are among the names read. (3) 19 release checks against the wheels by plain-text search agree:

Limits

  • Nothing was installed or run. "Has it" means the import statement resolves in the Python files of the wheel; an operator that needs the compiled extension (torchvision.ops.nms on a build without it) can still fail at call time.
  • Patch releases are not read: a name added or removed in x.y.1 shows up at the next minor. torchvision before 0.3.0 is not covered.

Questions

How do I fix "No module named 'torchvision.transforms.functional_tensor'" (basicsr, Real-ESRGAN, GFPGAN)?

torchvision 0.17.0 (2024-01-30) removed the module; 0.16.x warned that it would. basicsr 1.4.2, the latest basicsr on PyPI (2022), still has from torchvision.transforms.functional_tensor import rgb_to_grayscale in basicsr/data/degradations.py, line 8; Real-ESRGAN 0.3.0 and GFPGAN 1.3.8 require basicsr>=1.4.2. Change that line to from torchvision.transforms.functional import rgb_to_grayscale (for a tensor it calls the same code), or pin torchvision<0.17 (0.16.2 needs torch 2.1.2).

How do I fix "cannot import name 'read_video' from 'torchvision.io'"?

torchvision 0.26.0 (2026-03-23) removed video decoding: read_video, read_video_timestamps, write_video and VideoReader are gone from torchvision.io, and so are the modules torchvision.io.video and torchvision.io.video_reader. From 0.28.0 the wheel has a torchvision/io/video.py again, but it imports a Meta-internal package and fails. Use TorchCodec (pip install torchcodec; from torchcodec.decoders import VideoDecoder), or pin torchvision<0.26 (0.25.0 needs torch 2.10.0). Image decoding (read_image, decode_jpeg) is still there.

How do I fix "No module named 'torchvision.models.utils'"?

torchvision 0.11 (2021-10-21) removed it; 0.10.1 is the last release with it. Its one useful name was load_state_dict_from_url: use from torch.hub import load_state_dict_from_url.

Which torchvision version goes with my torch?

Each torchvision wheel on PyPI pins one torch release exactly: torchvision 0.16.2 requires torch==2.1.2, 0.25.0 requires torch==2.10.0. pip install torchvision without a version can therefore up- or downgrade torch. From 0.29.1 the pin is torch>=2.14.0. The table on this page lists every release.

Where did torchvision.datapoints go?

torchvision 0.16.0 (2023-10-04) renamed it torchvision.tv_tensors, and renamed a few v2 transforms (ToImageTensor to ToImage, ConvertDtype to ToDtype, ClampBoundingBox to ClampBoundingBoxes, SanitizeBoundingBox to SanitizeBoundingBoxes).
